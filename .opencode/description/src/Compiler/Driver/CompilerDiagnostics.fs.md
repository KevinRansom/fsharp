# CompilerDiagnostics.fs

**Purpose** The diagnostic output pipeline. Takes a `PhasedDiagnostic` (or one of the many legacy `exn`-based errors raised by the lexer/parser/typechecker) and turns it into a formatted, filtered, severity-adjusted message. This is the single place that controls how errors, warnings, and infos look in fsc/fsi — including rich-text rendering, name suggestions, code-context caret lines, and the `DiagnosticStyle` variants (`Emacs`, `Gcc`, `Test`, `VisualStudio`, `Default`, `Rich`).

**Pipeline role** Terminal of the diagnostic flow: every `warning`/`error` across the driver and checkers ends up here, either as an `exn` (legacy) or as a `PhasedDiagnostic` (modern); this module normalizes them (`AdjustSeverity`), formats them (`FormatCore`/`FormatRichCore`), filters them (the nowarn logger), and renders them to a `StringBuilder`/`TextWriter`. `fsc.fs` installs a logger from this module via `GetDiagnosticsLoggerFilteringByScopedNowarn`.

**Namespace(s)** `FSharp.Compiler` — module `FSharp.Compiler.CompilerDiagnostics`, declared `internal`.

**Type extension — `PhasedDiagnostic with`** (line ~357 and line ~2372)
- `Range`, `Number`, `EagerlyFormatCore suggestNames`, `FormatRichCore (flattenErrors, suggestNames) -> RichText`, `FormatCore ... -> string`, `AdjustSeverity FSharpDiagnosticOptions -> FSharpDiagnosticSeverity`, `Output (buf, tcConfig, severity)`, `OutputContext (buf, prefix, fileLineFunction)`, `WriteWithContext (os, prefix, fileLineFunction, tcConfig, severity)`.
- `AdjustSeverity` is where all the "warn on/off/as-error" decisions live:
  - severity = Warning and in `WarnOff` → `Hidden`
  - severity = Warning and in `WarnAsErrors` → `Error`
  - severity = Info and in `WarnOn` and not in `WarnOff` → `Warning`
  - severity = Info and enabled (per `diagnosticOptions` and `warnOff`) → `Info`
  - otherwise → `Hidden`

**Class declarations**
- `DiagnosticsLoggerFilteringByScopedNowarn` (inherits `DiagnosticsLogger`, line ~2438) — wraps a delegate logger; tracks whether a *real* error (not just a warning) has been seen (`realErrorPresent`); its `DiagnosticSink` first adjusts severity via `diagnostic.AdjustSeverity diagnosticOptions` and routes hidden ones to no-op, then forwards the rest with the adjusted severity. `ErrorCount` is the delegate's; `CheckForRealErrorsIgnoringWarnings` reports `realErrorPresent`.

**Internal helpers / active patterns** See the lists above (per-token message bindings, the two big `Exception` match arms, the context-info emitters).

**Significant internal logic**
- **Two-level exception mapping:** the first `with` block extracts the *range* (`Some range | None`), the second extracts the *message* (via the `OldStyleMessages.*E` bindings or a `DiagnosticMessage`). This split lets one `PhasedDiagnostic` carry both at once.
- **`AdjustSeverity` centralizes warn-logic** (`WarnOn`, `WarnOff`, `WarnAsErrors`, `CheckNullness`, `CheckOverflow`) in one place.
- **`OldStyleMessages` is `[<AutoOpen>]`** so the `...E()` builders are in scope wherever a message string is needed, and the `Message`/`DeclareResourceString` call gives each legacy message its resource key + argument format.
- **`DiagnosticsLoggerFilteringByScopedNowarn`** is the logger installed by `fsc.fs` (`GetDiagnosticsLoggerFilteringByScopedNowarn`) so that `#nowarn`/scoped pragmas suppress warnings but never real errors, and so that `ErrorCount` / "check for real errors" logic in the driver is correct.
- **`Output` / `WriteWithContext`** order the output per `DiagnosticStyle`: Emacs / Gcc / Test / VisualStudio / Default show location first, then context, then canonical, then message; `Rich` puts the canonical+message first and then adds location/context for readability.
