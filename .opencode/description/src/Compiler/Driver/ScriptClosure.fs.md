# ScriptClosure.fs

**Purpose** Computes the "load closure" of a set of F# scripts: the transitive set of `#load`ed source files and `#r`ed references (plain file references plus package-manager references) that the root scripts bring in, together with the per-file parse and directive diagnostics and the resulting `TcConfig` accumulation. This is the stage that runs *before* `TcImports` is built, so both `fsc` (when the roots are scripts) and F# Interactive / FCS know the exact set of sources and references to compile.

**Pipeline role** Invoked from fsc `main1` (via `fsc.fs AdjustForScriptCompile → LoadClosure.ComputeClosureOfScriptFiles`) and from FCS (via the `ComputeClosureOfScriptText` static member). The `LoadClosure` it returns is what the driver uses to expand the source-file list and to add the `#r`ed references to `TcConfigBuilder` before it builds `TcImports` and runs the check.

**Namespace(s)** `FSharp.Compiler` — module `FSharp.Compiler.ScriptClosure`, `internal`.

**Types declared**
- `CodeContext` — `CompilationAndEvaluation | Compilation | Editing` — which mode a directive is legal in, and which `LegacyResolutionEnvironment` + `conditionalDefines` to use (see `ParseScriptClosureInput`: `CompilationAndEvaluation → ["INTERACTIVE"]`, `Compilation → ["COMPILED"]`, `Editing → ["EDITING"] + (INTERACTIVE | COMPILED depending on IsScript fileName)`).
- `LoadClosureInput` — `{ FileName; SyntaxTree: ParsedInput option; ParseDiagnostics: PhasedDiagnostic list; MetaCommandDiagnostics: PhasedDiagnostic list }`.
- `LoadClosure` — the aggregate result; see `.fsi` for the full record shape (`SourceFiles`, `References`, `PackageReferences`, `PackageManagerLines`, `UseDesktopFramework`, `SdkDirOverride`, `UnresolvedReferences`, `Inputs`, `OriginalLoadReferences`, `ResolutionDiagnostics`, `AllRootFileDiagnostics`, `LoadClosureRootFileDiagnostics`).

**Module `ScriptPreprocessClosure`** (line ~81, all internal to the module)
- **`ClosureSource`** — `ClosureSource of fileName * referenceRange * sourceText: ISourceText * Position option * parseRequired: bool`; a node in the closure walk.
- **`ClosureFile`** — `ClosureFile of fileName * range * parsedInput: ParsedInput option * parseDiagnostics * metaDiagnostics`; a *produced* file in the closure (one per visited script or non-script leaf).
- **`Observed`** (line ~96) — a `HashSet<fileName, bool>` wrapper with `SetSeen` / `HaveSeen`; the cycle-breaker that stops a `#load`-loop from diverging (`if not (observedSources.HaveSeen fileName) then ...`).
- **`ParseScriptClosureInput (fileName, sourceText, tcConfig, codeContext, lexResourceManager, diagnosticsLogger)`** (line ~106) — builds the `conditionalDefines` list per `codeContext` (see above), clones the `TcConfig` and applies those defines, makes a `LexBuffer` via `UnicodeLexing.SourceTextAsLexbuf`, computes `isLastCompiland = (IsScript fileName, tcConfig.target.IsExe)`, and calls `ParseAndCheckInputs.ParseOneInputLexbuf`.
- **`CreateScriptTextTcConfig (...)`** (line ~144) — the FCS-only path (used by `ComputeClosureOfScriptText`): builds a fresh `TcConfigBuilder` from raw flags (`legacyReferenceResolver`, `defaultFSharpBinariesDir`, `reduceMemoryUsage`, `isInteractive`, `isInvalidationSupported`, `CopyFSharpCoreFlag.No`, `tryGetMetadataSnapshot`, `sdkDirOverride`), then sets the primary assembly from `assumeDotNetFramework` (`Mscorlib` vs `System_Runtime`), sets `useSdkRefs`, applies `applyCommandLineArgs` (the host's own flag function), and — if `basicReferences` is `None` — calls `tcConfigB.FxResolver.GetDefaultReferences useFsiAuxLib` to obtain the default references (capturing diagnostics, and *adjusting the primary assembly* if the resolver reverted to the other framework — a real code path the file comments on). Sets `resolutionEnvironment` (per `codeContext`), `implicitlyReferenceDotNetAssemblies <- false`, `useSimpleResolution`, `implicitlyResolveAssemblies <- false`, `SetUseSdkRefs useSdkRefs`, and returns `TcConfig.Create (validate = true)`.
- **`ClosureSourceOfFilename (fileName, m, inputCodePage, parseRequired)`** (line ~244) — opens a script file (with the given code page, if any) and builds a single-elt `ClosureSource` list; recovers on `RecoverableException`.
- **`ApplyMetaCommandsFromInputToTcConfig`** (line ~260) — local clone of the namesake in `ParseAndCheckInputs` that *recovers* on `ReportedError` (falls back to a default config built from a fresh clone). Calls `ProcessMetaCommandsFromInput` with the two callbacks `addReferenceDirective` (via `TcConfigBuilder.AddReferenceDirective`) and `addLoadedSource` (via `TcConfigBuilder.AddLoadedSource`).
- **`getDirective d`** — the `r` / `i` letter for a `Directive.Resolution | Directive.Include`.
- **`FindClosureFiles (mainFile, closureSources, origTcConfig, codeContext, lexResourceManager, dependencyProvider)`** (line ~288) — the heart of the walk. Internally it builds `observedSources`, a `loadScripts` set, a `packageReferences: Dictionary<range, string list>`, and a mutable `tcConfig` that *accumulates* the `#r`s discovered as the walk proceeds. The inner mutually-recursive functions:
  - `resolveDependencyManagerSources scriptName caret` (line ~305) — walks `tcConfig.packageManagerLines`, filters lines whose range contains the editor caret (so an "in-flight" `#r` under the cursor is not resolved yet), and dispatches each remaining key to `processPackageManagerLines`.
  - `reportError m` (line ~329) — the `ResolvingErrorReport` closure that turns `ErrorReportType.Warning | .Error` into `warning`/`errorR` with the right `range`.
  - `processPackageManagerLines m lines scriptName key` (line ~337) — short-circuits if the lines are identical to a previous run (memoization across re-walks); otherwise `dependencyProvider.TryFindDependencyManagerByKey` and, if `Null`, builds a `CreatePackageManagerUnknownError` diagnostic; else calls `resolvePackageManagerLines`.
  - `resolvePackageManagerLines m lines scriptName key dm` (line ~371) — builds `packageManagerTextLines = (directive-letter, line) list`, gets `(tfm, rid) = tcConfig.FxResolver.GetTfmAndRid()`, calls `dependencyProvider.Resolve (dm, ".fsx", lines, report, tfm, rid, implicitIncludeDir, mainFile, scriptName)`. On `result.Success`:
    - writes `StdOut`/`StdError` to the console *unless* `codeContext = Editing` (so FCS does not spam the host's console);
    - reads each of `result.SourceFiles` into `packageReferences[m]` (the raw package-manager *lines*, keyed by the directive's range);
    - if there are roots, clones the config, adds them as include paths, and marks the lines as `Processed` (`PackageManagerLine.SetLinesAsProcessed`);
    - if there are resolutions, clones the config and adds them as referenced assemblies;
    - recurses into each of `result.SourceFiles` via `processClosureSource (ClosureSource(script, m, text, None, true))`.
  - On `result.Success = false`: writes any `StdOut`/`StdError` as `packageManagerError` diagnostics, and removes the unprocessed lines from the config (so a failing `#r` is not re-tried).
  - `processClosureSource (ClosureSource ...)` (line ~448) — the per-file handler. Skips if the filename has already been seen (cycle break). For a *script* or a file that must be parsed:
    - `ParseScriptClosureInput` to get the `ParsedInput` (with captured parse diagnostics);
    - `ApplyMetaCommandsFromInputToTcConfig` to pull the `#r`/`#load` lines into the config (this is where the `#r`-driven `tcConfig` mutation happens, and it is *cumulative* — the file's comment at line ~471 says "// We accumulate the tcConfig in order to collect assembly references");
    - `resolveDependencyManagerSources fileName caret` *before* and *after* the meta-commands so that package-manager lines introduced by the meta-commands are also resolved;
    - computes the newly-added sources as `postSources[preSources.Length ..]` (delta between `tcConfig.GetAvailableLoadedSources()` before and after); for each new sub-file: if it is a script, recurse via `processClosureSource (ClosureSourceOfFilename subFile ...)`; otherwise emit a `ClosureFile` leaf.
    - Finally yields `ClosureFile (fileName, m, Some parseResult, parseDiagnostics, metaDiagnostics)`.
  - For a non-script leaf (`else` branch at line ~494): yields `ClosureFile (fileName, m, None, [], [])` without traversing further (comment: "// Don't traverse into .fs leafs").
- **`MarkLastCompiland (tcConfig, lastClosureFile)`** (line ~508) — takes the last `ClosureFile` in the closure and, if it is an impl file, rewrites its `ParsedImplFileInput`'s `isLastCompiland` to `(true, tcConfig.target.IsExe)` so the entry point goes on the last file (the driver's `ComputeCanContainEntryPoint` contract).
- **`GetLoadClosure (rootFilename, closureFiles, tcConfig, codeContext, packageReferences, earlierDiagnostics)`** (line ~530) — folds `closureFiles` (after marking the last compiland) into a `LoadClosure` record: `sourceFiles`, `sourceInputs` (the `LoadClosureInput list` with `SyntaxTree` / `ParseDiagnostics` / `MetaCommandDiagnostics`), then the rest of the record (references, package references, `UseDesktopFramework`, `SdkDirOverride`, `UnresolvedReferences`, `OriginalLoadReferences`, the three diagnostic lists — assembled by the continuation of this function not shown above).

**Public API surface**
- `LoadClosure.ComputeClosureOfScriptText legacyReferenceResolver defaultFSharpBinariesDir fileName sourceText caret implicitDefines useSimpleResolution useFsiAuxLib useSdkRefs sdkDir lexResourceManager applyCompilerOptions assumeDotNetFramework tryGetMetadataSnapshot reduceMemoryUsage dependencyProvider` — the FCS entry (a long parameter list is deliberate — the doc comment says it must synthesize a `TcConfig` from flags so that the closure matches the rest of the host's configuration). Internally: `CreateScriptTextTcConfig` + `FindClosureFiles` + `GetLoadClosure`.
- `LoadClosure.ComputeClosureOfScriptFiles tcConfig ((fileName, range) list) implicitDefines lexResourceManager dependencyProvider` — the fsc/fsi entry (see `fsc.fs AdjustForScriptCompile`). Internally: `FindClosureFiles` (using the *existing* `tcConfig`) + `GetLoadClosure`.

**Internal helpers / active patterns**
- `Observed` / `loadScripts` / `packageReferences` — the three mutable accumulators that make the walk iterative-ish and idempotent.
- `resolveDependencyManagerSources` / `processPackageManagerLines` / `resolvePackageManagerLines` — the three-way recursion for the dependency-manager (package) resolution path.
- `GetAvailableLoadedSources` (from `FSharp.Compiler.CompilerConfig`) used as a *delta* detector for which `#load`ed sources each file contributed.
- `PackageManagerLine.SetLinesAsProcessed` / `RemoveUnprocessedLines` — the mark-as-done / remove-on-failure bookkeeping.
- The two static members of `LoadClosure` themselves (line ~714 and line ~756) are the public surface.

**Significant internal logic**
- **The walk is deliberately memoized at three levels** — `Observed` for files, `loadScripts` for package-generated scripts, and `packageReferences` keyed by the *range of the directive* — because a long `#load`/`#r` chain revisits the same file or the same package directive (for a different `#load`er) and must not be re-resolved.
- **`tcConfig` accumulates across files.** Each file's `#r`s are applied to the *same* running config via `ApplyMetaCommandsFromInputToTcConfig` (line ~260), so a later file sees the references an earlier file added. This is a deliberate design: the doc note at line ~471 says it explicitly.
- **Editor-cursor awareness.** The walk takes an optional caret position, and `isEditorCursorInPackageLines` (line ~311) filters out package-manager lines whose range straddles the caret — this is what lets FCS show diagnostics for an "in-flight" `#r` line without resolving it (the user is still typing).
- **Stdout/stderr routing on non-Editing contexts** is gated by `codeContext <> CodeContext.Editing` (line ~394) so that FCS doesn't pollute the host console — a deliberate separation between "run in the terminal" (fsc/fsc-style) and "edit in an IDE" (FCS) modes.
- **Framework selection is decided per file.** `CreateScriptTextTcConfig` (line ~205) *adjusts* `primaryAssembly` if the resolver reverted from Core to Framework (or vice-versa); in the `ComputeClosureOfScriptFiles` path the same adjustment is applied at the fsc level (`fsc.fs AdjustForScriptCompile` sets `PrimaryAssembly.Mscorlib` vs `System_Runtime` based on `closure.UseDesktopFramework`).
- **`MarkLastCompiland`** (line ~508) is the F#-specific rule that "the entry point is in the last file" — the file rewrites the last file's `ParsedImplFileInput.isLastCompiland` so `fsc.fs` and the check can use `ComputeCanContainEntryPoint` directly.
