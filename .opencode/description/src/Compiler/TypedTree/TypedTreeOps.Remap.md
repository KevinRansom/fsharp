# TypedTreeOps.Remap.fs

**Purpose**: The foundational type-level remapping toolkit of the TypedTreeOps layer. A `Remap` is a mapping of typars→types, tycons→tycons, vals→vals, with helpers to build, apply, compose and invert such mappings. This is the core machinery behind type instantiation (`instType`/`instTypes`), generalization (`generalizeTypar(s)`), and the `copyAndRemapAndBindTypars` used everywhere typars are re-scoped. It also provides the `TypeEquivalence` (structural alpha-equivalence), `TypeDecomposition`, `TypeBuilders` and `MeasureOps` modules used throughout checking and codegen.

**Namespace(s)**: `FSharp.Compiler.TypedTreeOps`.

**Significant internal logic**: A `Remap` is a `(TyconRefMap<TyconRef> * TyparInstantiation)` pair (tycon-identity remap + typar-to-type instantiation). `copyAndRemapAndBindTypars`/`copyAndRemapAndBindTyparsFull` is the core "re-scope typars" operation: it rewrites the typars' identities and extends the remap to bind the new typars to concrete instantiation types. `generalizeTypar(s)` builds a fresh typar→measure/type binding. `instType`/`instTypes` apply a `TyparInstantiation` to a type. `TypeEquivalence` (`typeEquiv`) is the structural, alpha-equivalence (ignoring typar identity, comparing up to the erasure and the given `TypeEquivEnv`) used for val/tycon identity decisions.
